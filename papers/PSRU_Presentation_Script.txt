[องค์ประกอบและเนื้อหาจริงบนสไลด์]:
- หัวข้อสไลด์: THE PROBLEM (ความท้าทายและโอกาสในการพัฒนา)
- ข้อความเกริ่นนำบนสไลด์ (Subtitle/Lead):
  จากการศึกษาเบื้องต้นและประสบการณ์เดินทางจริง ต่อยอดจากตารางการเดินรถเดิมของมหาวิทยาลัย

[กล่อง 01: ปัญหาที่พบ]
ผู้ใช้บริการยังไม่มีการแสดงตำแหน่งสดและเวลาที่รถจะมาถึง (ETA) ไม่ทราบสถานะความจุของรถ (ว่าง/เต็ม/พัก) 
ทำให้ต้องยืนรอตามจุดรับ-ส่งโดยไม่สามารถกะเวลาได้แน่นอน และผู้ดูแลระบบยังขาดข้อมูลความต้องการและสถิติแบบเรียลไทม์

[กล่อง 02: ใครได้รับผลกระทบ]
ส่งผลกระทบต่อนักศึกษาและบุคลากรที่ต้องการความแม่นยำในการวางแผนเดินทาง กลุ่มผู้สูงอายุ ผู้พิการ 
และผู้มาติดต่อที่ต้องการความสะดวกสบายในการเข้าถึงบริการ ตลอดจนคนขับและผู้บริหารที่ต้องการข้อมูลช่วยจัดสรรรอบ
เดินรถให้สอดคล้องกับความต้องการจริง

[กล่อง 03: ทำไมปัญหานี้สำคัญ]
เป็นโอกาสในการยกระดับคุณภาพชีวิตช่วยให้วางแผนเวลาได้อย่างมั่นใจ ต่อยอดให้รถไฟฟ้าที่มีอยู่ถูกใช้งานคุ้มค่าเต็มศักยภาพสูงสุด 
และเป็นก้าวสำคัญในการผลักดันมหาวิทยาลัยสู่ Smart & Green University

[ตัวเลขสถิติด้านล่าง]
60% ต้องการทราบสถานะและตำแหน่งรถล่วงหน้าขณะรอ | 90% ต้องการระบบติดตามตำแหน่งสดและคำนวณ ETA แบบเรียลไทม์

[บทพูดนำเสนอ - สำนวนธรรมชาติ ลื่นไหล]:
[บทเกริ่นนำเข้าสู่สไลด์]:
"ทุกท่านครับ จากการศึกษาเบื้องต้นและประสบการณ์การเดินทางจริงภายในมหาวิทยาลัย ถึงแม้ว่าทางมหาวิทยาลัยของเราจะมีตารางการเดินรถไฟฟ้าคอยให้บริการอยู่แล้ว แต่ในทางปฏิบัติ ผู้ใช้บริการยังคงต้องเผชิญกับความไม่แน่นอนในการรอคอย นำมาสู่ประเด็นปัญหาและผลกระทบสำคัญที่ปรากฏอยู่บนหน้าจอนี้ครับ [ผายมือไปที่หน้าจอ]"

[บทพูดนำเสนอเนื้อหา]:
"เมื่อเราดูข้อมูลที่เชื่อมโยงกันทั้งหมด [ชี้ไปที่กล่อง 01: ปัญหาที่พบ] ปัญหาหลักที่ทุกคนพบเจอในชีวิตประจำวัน คือการยืนรอรถตามจุดจอดโดยไม่มีการแสดงตำแหน่งสด และไม่รู้เวลาที่แน่นอนว่ารถจะมาถึงเมื่อไหร่ (ETA) อีกทั้งยังไม่ทราบสถานะความจุว่าคันที่กำลังแล่นมานั้นว่างหรือเต็ม ทำให้ผู้โดยสารกะเวลาไม่ได้แน่นอน และผู้ดูแลระบบเองก็ขาดข้อมูลสถิติแบบเรียลไทม์ในการจัดสรรรถ [ผายมือเชื่อมโยงไปที่กล่อง 02: ใครได้รับผลกระทบ] ซึ่งส่งผลกระทบโดยตรงต่อทุกคนในมหาวิทยาลัยครับ ทั้งนักศึกษาและบุคลากรที่ต้องการความแม่นยำในการเดินทางไปเรียนและทำงาน กลุ่มผู้สูงอายุ ผู้พิการ และผู้มาติดต่อที่ต้องการความสะดวกสบายในการเข้าถึงบริการขนส่ง ตลอดจนพนักงานขับรถและผู้บริหารที่ต้องการข้อมูลมาช่วยจัดสรรรอบเดินรถให้สอดคล้องกับความต้องการจริง [ผายมือไปที่กล่อง 03: ทำไมปัญหานี้สำคัญ] เหตุผลที่ปัญหานี้มีความสำคัญอย่างยิ่ง เพราะนี่คือโอกาสในการยกระดับคุณภาพชีวิตของทุกคน ช่วยให้รถไฟฟ้าที่มีอยู่ถูกใช้งานอย่างคุ้มค่าเต็มศักยภาพสูงสุด และเป็นก้าวสำคัญในการผลักดันมหาวิทยาลัยสู่ Smart & Green University [เน้นเสียงที่ตัวเลขสถิติด้านล่าง] ซึ่งยืนยันด้วยผลสำรวจด้านล่างครับว่า ผู้ใช้งานถึง 60% ต้องการทราบสถานะและความจุของรถล่วงหน้าขณะรอ และมากถึง 90% ต้องการระบบติดตามตำแหน่งสดและคำนวณเวลา ETA แบบเรียลไทม์ครับ"

[องค์ประกอบและเนื้อหาจริงบนสไลด์]:

- ข้อความเกริ่นนำบนสไลด์ (Subtitle/Lead):
  การลงพื้นที่ศึกษาอย่างเป็นระบบ เพื่อค้นหากุญแจสำคัญสู่การเปลี่ยนผ่านจากการเดินรถตามรอบเวลา สู่บริการอัจฉริยะแบบเรียลไทม์

[กล่อง 01: 01 OBSERVE (สิ่งที่พบ)]
จากการลงพื้นที่สำรวจจริงพบว่า ผู้โดยสารต้องยืนรอตามจุดรับ-ส่งโดยไร้ข้อมูลตำแหน่งสดและเวลาที่แน่นอน 
ในขณะที่คนขับก็อาจขับผ่านจุดจอดที่มีผู้โดยสารรอรับบริการอยู่โดยไม่ทราบล่วงหน้า

[กล่อง 02: 02 RESEARCH (ผลสำรวจความต้องการ N=30)]
[วางภาพกราฟผลสำรวจ Google Forms: ฟีเจอร์ที่ต้องการมากที่สุด]
ผลการสำรวจกลุ่มตัวอย่าง 30 คน พบความต้องการสอดคล้องกันอย่างชัดเจน โดย 90% ต้องการแผนที่ดูตำแหน่งรถสดแบบเรียล
ไทม์เป็นอันดับ 1 และ 80% ต้องการระบบประมาณเวลาที่จะมาถึง (ETA) เป็นอันดับ 2

[กล่อง 03: 03 INSIGHT (กุญแจสำคัญ)]
มหาวิทยาลัยมีระบบรถรับส่งไฟฟ้าที่ดีอยู่แล้ว แต่สิ่งที่ผู้ใช้งานทุกคนต้องการอย่างแท้จริงคือการเชื่อมโยงข้อมูลสดแบบเรียลไทม์ 
เพื่อเปลี่ยนผ่านจากการเดินรถตามรอบเวลาสู่บริการอัจฉริยะ

[ข้อความสรุปด้านล่าง]
คำถามหลัก: “กุญแจสู่ความสำเร็จคืออะไร?” สู่คำตอบการเปลี่ยนผ่านจากการเดินรถตามรอบเวลา สู่แพลตฟอร์มบริการอัจฉริยะ
ที่สื่อสารสองทางแบบเรียลไทม์

[บทพูดนำเสนอ - สำนวนธรรมชาติ ลื่นไหล]:
[บทเกริ่นนำเข้าสู่สไลด์]:

"ในสไลด์สุดท้ายนี้ ขอสรุปหัวใจสำคัญว่าทำไมผลงานชิ้นนี้จึงเป็นนวัตกรรมที่สร้างคุณค่าอย่างแท้จริงครับ [ชี้ไปที่การ์ดสรุปคุณค่าทั้ง 3 มิติ] เราเริ่มต้นจากการแก้ปัญหาความไม่แน่นอนในการรอคอย ด้วยนวัตกรรมแพลตฟอร์มที่เชื่อมโยงทุกคนเข้าด้วยกัน ผสาน Map Matching ตรึงหมุดแม่นยำ การคำนวณเวลา ETA และระบบเสียงแจ้งเตือนภาษาไทย จนสร้างผลกระทบให้ทุกคนวางแผนเวลาได้อย่างมั่นใจ มีความคุ้มค่าสูงสุด และผลักดันมหาวิทยาลัยสู่ Smart & Green University อย่างเป็นรูปธรรม ดั่งสโลแกนของเราครับ [เน้นเสียงอย่างมั่นใจ ชัดเจน และทรงพลัง] 'เรียกรถง่าย ติดตามได้ รู้เวลาถึง เชื่อมทุกจุดใน PSRU' [ผายมือไปที่ QR Code ทั้งสองฝั่งบนหน้าจอ] และในโอกาสนี้ กระผมขอเรียนเชิญท่านคณะกรรมการทุกท่าน สแกน QR Code ด้านซ้ายเพื่อทดลองใช้งาน Live Web Demo บนสมาร์ตโฟนของท่านได้ทันทีครับ หรือสแกนด้านขวาเพื่อดาวน์โหลดไฟล์ติดตั้ง Android APK กระผมขอจบการนำเสนอแต่เพียงเท่านี้ ขอขอบพระคุณท่านคณะกรรมการทุกท่านเป็นอย่างสูง และพร้อมตอบทุกข้อซักถามครับ"

[ยืนตรง ยกมือไหว้ขอบคุณอย่างสุภาพ สบตากรรมการเพื่อพร้อมรับคำถาม]

คำถามที่ 1: ทำไมถึงเลือกใช้ OpenStreetMap แทนที่จะใช้ Google Maps API?
แนวทางการตอบ:
"เหตุผลหลักมี 2 ประการครับอาจารย์
1. ด้านต้นทุน (Cost Efficiency): Google Maps มีการคิดค่าบริการ API เป็นรายเดือนตามจำนวน Request ซึ่งการติดตามพิกัดรถแบบเรียลไทม์จะมีการส่งพิกัดทุกๆ 1-3 วินาที หากใช้ Google Maps จะทำให้มหาวิทยาลัยมีภาระค่าใช้จ่ายมหาศาล แต่ OpenStreetMap เป็นระบบเปิดที่ไม่มีค่าใช้จ่าย API จึงทำให้ต้นทุนเป็นศูนย์ (Zero API Cost)
2. ด้านความยืดหยุ่นในการปรับแต่ง (Flexibility): ถนนภายในมหาวิทยาลัยอาจมีเส้นทางเฉพาะหรือจุดตัดที่ Google Maps ยังไม่ได้อัปเดต การใช้ OpenStreetMap ร่วมกับ Flutter Map ช่วยให้เราสามารถวาดโครงข่ายถนนและกำหนดจุดจอดของมหาวิทยาลัยลงในกราฟเพื่อคำนวณ Map Matching ได้แม่นยำ 100% ครับ"

คำถามที่ 2: อัลกอริทึม Map Matching แก้ปัญหา GPS Drift ได้อย่างไร? มีหลักการอย่างไร?
แนวทางการตอบ:
"สัญญาณ GPS จากสมาร์ตโฟนเมื่ออยู่ใกล้ตึกสูง มักจะมีสัญญาณสะท้อนทำให้พิกัดกระโดดออกนอกถนน (GPS Drift)
เราแก้ปัญหานี้ด้วยขั้นตอนวิธี Vector Orthogonal Projection หรือการฉายเวกเตอร์ตั้งฉากครับ โดยระบบจะแปลงเส้นทางถนนทั้งหมดในมหาวิทยาลัยเป็นโครงข่าย Segment เส้นตรง เมื่อได้รับพิกัด GPS ดิบเข้ามา ระบบจะคำนวณหาระยะทางตั้งฉากที่สั้นที่สุดไปยังเส้นถนนที่ใกล้ที่สุด แล้วดึงหมุดรถ (Snap) เข้ามาวางบนกึ่งกลางถนนจริงทันที ทำให้รถแล่นอยู่บนถนนอย่างต่อเนื่อง ไม่กระโดดหลุดเข้าไปในตัวอาคารครับ"

คำถามที่ 3: ระบบสถาปัตยกรรม Hybrid Cloud ของ Firebase ช่วยลดค่าใช้จ่ายอย่างไร?
แนวทางการตอบ:
"ถ้าเราใช้ Cloud Firestore บันทึกตำแหน่ง GPS ของรถทุกๆ 1-2 วินาที จำนวนครั้งในการอ่านและเขียนข้อมูล (Document Reads/Writes) จะพุ่งสูงขึ้นอย่างรวดเร็วจนเกินโควต้าฟรีและมีค่าบริการสูง
เราจึงแยกบทบาทของฐานข้อมูลออกเป็น 2 ชั้นครับ:
1. ข้อมูลพิกัดรถและสถานะสด ซึ่งมีการอัปเดตตลอดเวลา เราส่งผ่าน Firebase Realtime Database (RTDB) ซึ่งคิดค่าบริการตามขนาดข้อมูล (Bandwidth) ไม่คิดตามจำนวนครั้งในการเขียน ทำให้ประหยัดค่าใช้จ่ายได้มหาศาลและได้ความหน่วงต่ำ (Low Latency)
2. ข้อมูลระบบ บัญชีผู้ใช้ ประวัติการเรียกรถ และระบบแชท เราเก็บไว้บน Cloud Firestore เพื่อความปลอดภัยและการจัดโครงสร้างข้อมูลที่ซับซ้อน จึงทำให้ระบบเสถียรและประหยัดงบประมาณได้สูงสุดครับ"

คำถามที่ 4: ทำไมจึงต้องมีระบบเสียงขานชื่อจุดจอดภาษาไทย (TTS) บนหน้าจอของคนขับ?
แนวทางการตอบ:
"เราออกแบบระบบโดยยึดหลัก Safety-First ครับ เพราะพนักงานขับรถต้องใช้สมาธิในการมองถนน หากต้องคอยก้มมองหน้าจอสมาร์ตโฟนว่ามีผู้โดยสารเรียกหรือไม่ หรือกำลังจะถึงป้ายใด อาจก่อให้เกิดอุบัติเหตุได้
ระบบของเราจึงติดตั้ง Text-to-Speech ขานชื่อจุดจอดเป็นภาษาไทยเมื่อรถวิ่งเข้าใกล้จุดจอดในระยะที่กำหนด และมีเสียงสัญญาณเตือนทันทีเมื่อมีผู้โดยสารกดเรียกรถ ทำให้คนขับสามารถรับทราบข้อมูลได้โดยไม่ต้องละสายตาจากถนนครับ"

คำถามที่ 5: หากมหาวิทยาลัยต้องการนำระบบนี้ไปใช้งานจริง มีความพร้อมแค่ไหนและต้องลงทุนอะไรเพิ่มบ้าง?
แนวทางการตอบ:
"ระบบของเรามีความพร้อมในระดับ Production-Ready สำหรับต้นแบบแล้วครับ
สิ่งที่ต้องจัดเตรียมเพิ่มเติมแทบไม่มีค่าใช้จ่ายด้านฮาร์ดแวร์เลยครับ เนื่องจาก:
1. ฝั่งคนขับ ใช้สมาร์ตโฟน Android ทั่วไปที่คนขับมีอยู่แล้ว ติดตั้งแอปพลิเคชันและวางไว้หน้ารถได้ทันที
2. ฝั่งผู้โดยสาร สามารถใช้งานผ่าน Web Application บนเว็บบราวเซอร์ได้ทันทีโดยไม่ต้องดาวน์โหลดแอป หรือติดตั้งผ่าน Android APK ก็ได้
3. โครงสร้างคลาวด์ใช้บริการของ Firebase ซึ่งในระดับการใช้งานภายในมหาวิทยาลัย ปริมาณการใช้งานจะอยู่ภายใต้แพ็กเกจฟรีหรือมีค่าใช้จ่ายที่ต่ำมากครับ"
