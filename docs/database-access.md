# สิทธิ์เขียนข้อมูลรถใน Realtime Database

กฎนี้ใช้รายการสิทธิ์ที่ผู้ดูแล Firebase เป็นผู้ตั้งค่า ไม่ใช้ `users.role`
ใน Firestore หรือ `driver_uid` ที่อยู่ในข้อมูลตำแหน่งรถเป็นหลักฐานสิทธิ์
นักศึกษาที่ล็อกอินอ่านตำแหน่งรถได้ แต่สร้าง แก้ไข และลบรถไม่ได้
คนขับสร้างและอัปเดตได้เฉพาะคีย์รถที่ได้รับมอบหมาย และต้องส่ง
`driver_uid` ของตนเอง ห้ามลบรถหรือถอด `driver_uid` ออก

## ตั้งค่าสำหรับบัญชีเดิมก่อน deploy

1. เปิด Firebase Authentication ในโปรเจกต์ที่ต้องการใช้งาน ตรวจสอบ UID
   ของบัญชีแอดมินตัวจริง อย่าใช้เพียงค่า role หรืออีเมลจากเอกสาร users
2. ใน Realtime Database Console เพิ่มค่า boolean `true` ที่
   `/access/admins/<ADMIN_UID>` เฉพาะบัญชีที่อนุมัติแล้ว
   client ทุกบัญชีรวมถึงแอดมินไม่สามารถเขียนรายการนี้ได้
3. ตรวจสอบรายการมอบหมายรถเดิมกับผู้ดูแลและ UID ใน Authentication
   แล้วเพิ่ม `/shuttle_drivers/<RTDB_KEY>` เป็น string UID ของคนขับ
   เช่น `/shuttle_drivers/shuttle_01` = `<DRIVER_UID>`
   อย่าคัดลอก `shuttles.driver_uid` เดิมมาให้สิทธิ์อัตโนมัติ เพราะข้อมูลนั้น
   เคยเปิดให้ผู้ใช้ทั่วไปเขียนได้ ตรวจทานข้อมูลพิกัด/สถานะเดิมด้วย
4. คีย์รถต้องตรงกับแอป: ใช้ตัวเลขจากหมายเลขรถก่อน แล้วเติมศูนย์อย่างน้อย
   สองหลัก เช่น `SH#01` เป็น `shuttle_01`; ถ้าไม่มีตัวเลขใช้ตัวเลขจากชื่อรถ
   และถ้ายังไม่มี ให้ใช้ Firestore document ID รถคันนั้น
   อย่ามอบหมายรถหลายเอกสารที่ได้คีย์เดียวกัน
5. เพิ่มข้อมูลเฉพาะ path ที่ระบุ อย่า import JSON ทับ root ของฐานข้อมูล
   ตัวอย่างด้านล่างเป็นโครงสร้างอ้างอิง ห้ามใช้ placeholder เป็น UID จริง

```json
{
  "access": { "admins": { "<ADMIN_UID>": true } },
  "shuttle_drivers": { "shuttle_01": "<DRIVER_UID>" }
}
```

6. ทดสอบใน Emulator ตาม [คู่มือทดสอบ](../tools/security-tests/README.md)
   แล้ว deploy เฉพาะกฎฐานข้อมูลไปยังโปรเจกต์ที่ตรวจสอบแล้ว:

```powershell
firebase deploy --only database --project <PROJECT_ID>
```

7. แจกจ่ายแอปเวอร์ชันนี้ให้แอดมินก่อนเพิ่มหรือเปลี่ยนคนขับครั้งต่อไป
   ลองให้คนขับเดิมส่ง GPS และสถานะรถ แล้วลองบัญชีนักศึกษาว่าเขียนไม่ได้

หากยังไม่มีรายการสิทธิ์ กฎจะปฏิเสธการเขียนโดยตั้งใจ ไม่ย้อนกลับไปใช้
กฎ `auth != null` เพื่อแก้ permission denied ตรวจ UID และคีย์รถแทน
กฎใน repository ไม่เปลี่ยนระบบจริงจนกว่าจะ deploy

## เพิ่ม เปลี่ยน และถอนสิทธิ์

หน้าสร้างคนขับตรวจสิทธิ์แอดมินก่อนสร้างบัญชี และมอบหมายสิทธิ์หลังบันทึกรถ
หน้าแก้ไขคนขับถอนสิทธิ์เดิมก่อนบันทึก แล้วมอบหมายคันที่เลือกใหม่
ธุรกรรมไม่อนุญาตให้ทับสิทธิ์ที่เป็นของคนขับคนอื่น
หากพบข้อความผิดพลาดระหว่างบันทึก ห้ามถือว่าการมอบหมายสำเร็จ
ให้ตรวจข้อมูลรถแล้วบันทึกซ้ำจากหน้าแก้ไขคนขับ

Firestore กับ RTDB ไม่มี transaction ร่วมกัน ขั้นตอนนี้จึงเลือกปฏิเสธ
สิทธิ์ไว้ก่อนหากการบันทึกล้มเหลว แทนการปล่อยสิทธิ์รถเดิมค้างอยู่
ผู้ดูแลสามารถถอนสิทธิ์ทันทีโดยลบ `/shuttle_drivers/<RTDB_KEY>`
รถที่ค้าง online จะหมดอายุตามระบบเดิม หรือแอดมินตั้ง offline ได้
ข้อมูลรถเก่าที่ใช้ UID/document ID เป็นคีย์ต้องตรวจทานและลบโดยผู้ดูแล
คนขับไม่ทำการลบข้อมูลเก่าอัตโนมัติอีกต่อไป

ขอบเขตการแก้ไขนี้คือ RTDB; ไม่ได้เปลี่ยน Firestore rules, ระบบ login
หรือการเลือก role ของผู้ใช้

อ้างอิง: [Firebase Security Rules](https://firebase.google.com/docs/database/security)
และ [เงื่อนไขใน RTDB Rules](https://firebase.google.com/docs/database/security/rules-conditions)
