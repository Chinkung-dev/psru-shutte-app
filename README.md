# PSRU Shuttle App

แอปพลิเคชันสำหรับติดตามและเรียกรถรับส่งภายในมหาวิทยาลัยราชภัฏพิบูลสงคราม พัฒนาด้วย Flutter และเชื่อมต่อบริการคลาวด์แบบ Real-time ด้วย Firebase (Cloud Firestore และ Realtime Database)

แอปพลิเคชันนี้ถูกออกแบบมาเพื่ออำนวยความสะดวกให้นักศึกษาสามารถดูตำแหน่งรถรับส่งแบบเรียลไทม์ผ่านโมเดล 3D ตรวจสอบเส้นทางเดินรถ ส่งสัญญาณแจ้งรอรถที่ป้าย และแชทสื่อสารกับคนขับรถได้ พร้อมระบบบริหารจัดการสำหรับคนขับและผู้ดูแลระบบ (Admin)

---

## ฟีเจอร์หลัก (Key Features)

### 1. แผนที่และการติดตามรถเรียลไทม์ (Live Map & 3D Shuttles)
* แสดงแผนที่ OpenStreetMap ภายในมหาวิทยาลัยผ่าน `flutter_map`
* แสดงหมุดจุดจอดรถรับส่ง (Bus Stops) และตำแหน่งรถปัจจุบัน
* เรนเดอร์โมเดลรถรับส่ง 3 มิติ (3D Model `.glb`) บนแผนที่จริงผ่าน `three_js`
* คำนวณองศาการเลี้ยวและทิศทางของหัวรถ (Heading Interpolation) อัตโนมัติตามการเคลื่อนที่จริง
* มีสวิตช์สำหรับสลับโหมดการแสดงผลระหว่างโมเดล 3D และหมุด 2D Badge

### 2. การคำนวณเส้นทางและจุดจอดอัจฉริยะ (Routing & Pathfinding)
* ระบบ Highlight Route อัลกอริทึมคำนวณเส้นทางด้วย Graph Pathfinding (Dijkstra) ลากเส้นถนนจากตำแหน่งรถไปยังจุดจอดเป้าหมายได้อย่างแม่นยำ
* เชื่อมต่อจุดตัดทางแยกบนโครงข่ายถนนมหาวิทยาลัยโดยอัตโนมัติ
* มีระบบจัดการเงื่อนไขการแวะและข้ามป้าย (Stop Bypass Logic เช่น เงื่อนไขป้ายที่ 5)

### 3. ระบบผู้ใช้งาน 3 บทบาท (Role-based Management)
* **นักศึกษา (Student):**
  * ดูตำแหน่งรถรับส่งแบบเรียลไทม์และเวลาโดยประมาณ
  * บันทึกจุดจอดโปรด (Favorite Stops) เพื่อเข้าถึงได้อย่างรวดเร็ว
  * ส่งสัญญาณ "แจ้งรอรถที่จุดนี้" ไปยังคนขับ
  * แชทพูดคุยกับคนขับประจำสายรถ พร้อมส่งรูปภาพ
  * ระบบเสียงแจ้งเตือนด้วย Text-to-Speech (TTS) เมื่อรถใกล้ถึง
  * ระบบ Onboarding แนะนำการใช้งานหน้าจอหลัก
* **คนขับรถ (Driver):**
  * ส่งพิกัด GPS อัตโนมัติขึ้นสู่ระบบ Realtime Database
  * อัปเดตสถานะการทำงาน (กำลังวิ่ง, เต็ม, พักรอบ, เลิกงาน)
  * รับการแจ้งเตือนเมื่อมีนักศึกษากดรอรถที่ป้าย พร้อมปุ่มกดรับทราบ
  * ตอบกลับข้อความแชทของนักศึกษา
* **ผู้ดูแลระบบ (Admin Dashboard):**
  * หน้าภาพรวมระบบ (Overview Dashboard)
  * หน้า Live Map ศูนย์กลาง ติดตามพิกัดของรถทุกคันพร้อมกันแบบเรียลไทม์
  * จัดการข้อมูลจุดจอดรถ (เพิ่ม, แก้ไขพิกัด, ลบป้ายรถ)
  * จัดการข้อมูลบัญชีคนขับรถและมอบหมายรถประจำตัว
  * จัดการข้อมูลบัญชีนักศึกษา
  * รายงานสถิติการใช้งานและการรอรถ (Analytics Tab)

### 4. ระบบแจ้งเตือนและแชทเรียลไทม์ (Communication & Alerts)
* ห้องแชทแยกตามสายการเดินรถ
* ส่งข้อความและไฟล์รูปภาพผ่าน Firebase Storage
* ระบบเสียงแจ้งเตือนแชทและแจ้งเตือนสถานะรถ

## สถาปัตยกรรมและเทคโนโลยี (Architecture & Tech Stack)

### Frontend
* **Framework:** Flutter (Dart)
* **UI Design:** ออกแบบด้วยธีมสีประจำมหาวิทยาลัย (เขียวเข้ม `#176A21` และโทนสีเขียวอ่อน) มุมโค้งมน สะอาดตา และรองรับการแสดงผล Responsive

### Backend & Cloud Services
* **Firebase Realtime Database (RTDB):** รับส่งข้อมูลพิกัด GPS (`lat`, `lng`), สถานะรถ และ Heartbeat แบบความถี่สูง เพื่อความรวดเร็วและประหยัดโควต้า
* **Cloud Firestore:** จัดเก็บข้อมูลโครงสร้างผู้ใช้ (`users`), จุดจอดรถ (`stops`), คำขอเรียกรถ (`ride_requests`), ประวัติแชท (`chats`), และสถิติ (`analytics`)
* **Firebase Authentication:** ระบบจัดการและยืนยันตัวตนผู้ใช้
* **Firebase Storage:** จัดเก็บไฟล์รูปภาพที่ส่งในห้องแชท (`chat_images`)

### แพ็กเกจสำคัญ (Core Dependencies)
* `flutter_map` และ `latlong2`: จัดการแผนที่ OpenStreetMap และการคำนวณพิกัด
* `three_js`: เรนเดอร์โมเดล 3D Bus บนแผนที่
* `firebase_database`: เชื่อมต่อ Firebase Realtime Database
* `cloud_firestore`: เชื่อมต่อ Cloud Firestore
* `firebase_auth`: ระบบเข้าสู่ระบบและสมัครสมาชิก
* `firebase_storage`: บริการจัดเก็บไฟล์ภาพ
* `flutter_tts`: แปลงข้อความเป็นเสียงพูดแจ้งเตือน (Text-to-Speech)
* `audioplayers`: เล่นเสียงเอฟเฟกต์แชทและการแจ้งเตือน
* `geolocator`: ดึงพิกัดตำแหน่งปัจจุบันของผู้ใช้งาน
* `tutorial_coach_mark`: แนะนำขั้นตอนการใช้งานสำหรับผู้ใช้ใหม่
* `google_fonts`: แบบอักษรภาษาไทยที่ทันสมัย (Kanit, Prompt)

## ระบบความปลอดภัย (Security Architecture)

โปรเจกต์นี้ได้รับการกำหนดค่าความปลอดภัยแบบหลายชั้น (Multi-tier Security Rules):

1. **Realtime Database (`database.rules.json`):**
   * ปิดการเข้าถึงระดับ Root (`.read: false`, `.write: false`)
   * ตรวจสอบสิทธิ์แอดมินผ่านพาธ `/access/admins/<UID>` โดยตรง
   * คนขับสามารถอัปเดตได้เฉพาะรถที่ได้รับมอบหมายใน `/shuttle_drivers/<shuttleId>` และต้องส่ง `driver_uid` ตรงกับตนเอง
   * ตรวจสอบความถูกต้องของช่วงพิกัดละติจูดและลองจิจูด
2. **Cloud Firestore (`firestore.rules`):**
   * ป้องกันการยกระดับสิทธิ์: ผู้ใช้ทั่วไปไม่สามารถแก้ไขฟิลด์ `role` ในเอกสาร `users` ของตนเองได้
   * คอลเล็กชัน `stops` เปิดให้อ่านเท่านั้น (Read-only) สำหรับผู้ใช้ทั่วไป และแก้ไขได้เฉพาะแอดมิน
   * คอลเล็กชัน `ride_requests` และ `chats` จำกัดสิทธิ์การสร้างและแก้ไขตาม UID จริงของผู้ใช้งาน
3. **Cloud Storage (`storage.rules`):**
   * อนุญาตให้อัปโหลดเฉพาะไฟล์รูปภาพ (`image/*`) ขนาดไม่เกิน 10 MB ในโฟลเดอร์ `chat_images`

## การเริ่มต้นใช้งาน (Getting Started)

### สิ่งที่ต้องเตรียม (Prerequisites)
* ติดตั้ง Flutter SDK (เวอร์ชัน 3.x ขึ้นไป)
* บัญชี Firebase สำหรับเชื่อมต่อโปรเจกต์
* เว็บบราวเซอร์, Android Emulator หรืออุปกรณ์จริง

### ขั้นตอนการรันแอปพลิเคชัน
1. ติดตั้ง Dependencies ทั้งหมด:
   ```bash
   flutter pub get
   ```
2. รันการทดสอบระบบ (Automated Tests):
   ```bash
   flutter test
   ```
3. รันแอปพลิเคชัน:
   ```bash
   # รันบนอุปกรณ์เริ่มต้น
   flutter run

   # รันบน Web Browser (แนะนำสำหรับการทดสอบฝั่งคนขับและแอดมิน)
   flutter run -d chrome
   ```

### การ Deploy กฎความปลอดภัยไปยัง Firebase
หากมีการแก้ไขกฎความปลอดภัย สามารถ Deploy ขึ้นสู่ Cloud ได้ผ่าน Firebase CLI:
```bash
firebase deploy --only firestore:rules,storage,database
```

## คำแนะนำสำหรับการทดสอบบนอุปกรณ์เคลื่อนที่

### การทดสอบแอปบน iPhone ผ่านคอมพิวเตอร์ Windows
สำหรับผู้พัฒนาที่ใช้ Windows สามารถทดสอบ UI/UX บน iPhone ได้สะดวกที่สุดผ่านโหมด Web Server ในเครือข่าย Wi-Fi เดียวกัน:

1. เชื่อมต่อคอมพิวเตอร์และ iPhone ให้อยู่ในวง Wi-Fi เดียวกัน
2. ค้นหาหมายเลข IP Address ของคอมพิวเตอร์ (เปิด Command Prompt พิมพ์ `ipconfig` ดูที่ IPv4 Address เช่น `192.168.1.45`)
3. รัน Flutter ในโหมด Web Server:
   ```bash
   flutter run -d web-server --web-hostname 0.0.0.0 --web-port 8080
   ```
4. เปิด Safari บน iPhone แล้วเข้า URL: `http://<IP-Address-ของคอมพิวเตอร์>:8080`
5. แนะนำให้กดปุ่ม **Share (แชร์)** ใน Safari แล้วเลือก **"Add to Home Screen" (เพิ่มไปยังหน้าจอโฮม)** เพื่อเปิดแอปแบบเต็มหน้าจอ

### การขอสิทธิ์ตำแหน่ง (Location Permission) บน Safari (iOS / Web)
* **กลไกความปลอดภัยของ Safari:** Safari จะไม่อนุญาตให้หน้าเว็บขอสิทธิ์พิกัดตำแหน่งอัตโนมัติหากผู้ใช้ยังไม่ได้สัมผัสหน้าจอ (User Gesture)
* **การแก้ไข:** เมื่อเปิดหน้าแผนที่ ให้แตะที่ **ปุ่มเป้าเล็ง GPS (มุมขวาล่างของแผนที่)** 1 ครั้ง เพื่อส่งสัญญาณให้ Safari แสดงกล่องข้อความขออนุญาตเข้าถึงตำแหน่ง
* **กรณีเคยถูกปฏิเสธสิทธิ์:** เข้าไปที่ **การตั้งค่า (Settings) > Safari > ตำแหน่งที่ตั้ง (Location)** และเปลี่ยนเป็น **"ถาม (Ask)"** หรือ **"อนุญาต (Allow)"**
